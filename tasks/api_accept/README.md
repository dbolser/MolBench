# Accept-set tier, API (pdbe-molstar 3.3.2 calls) track

Generated by `scripts/generate_accept_set_tasks.py` (seed `molbench-accept-set-v1`); do not edit.
Under-specified requests where several final states are all right. Every accepted
state is enumerated by script from the frozen panel (`data/panel/facts`, the atom
tables) and listed in the task: `reference` is the first, `accepted` the others,
`accepted_targets` their targets. `provenance` holds the rule that generated them
(`rule`), their names in order (`accepted_states`), what is not accepted and why
(`not_accepted`), and the difficulty facts (`difficulty`).

15 tasks on 12 structures; 3 tasks on 3 held-back structures; 15 have a twin on the other track.

## Templates

| family | tasks | accepted states per task | left open | example prompt |
|---|---:|---|---|---|
| `acc-ligand-which` | 3 | 3 | which of two different ligands (or both) | Open 1RX2 with the protein as a cartoon and the ligand in cyan ball-and-stick. |
| `acc-ligand-colours` | 3 | 2 | which ligand gets which colour | Show 1RX2 with the protein as a cartoon and the two ligands as ball-and-stick: one cyan, the other blue. |
| `acc-chain-colours` | 3 | 2 | which chain gets which colour | Load 1F88 and show it as a cartoon, with the two chains coloured orange and magenta. |
| `acc-ligand-copy` | 3 | 3 | which copy of the named ligand (or all) | Open 1IEP with the protein as a cartoon and the ligand STI in purple ball-and-stick. |
| `acc-residue-colour` | 3 | 3 | which chain's copy of the named residue (or all) | Show 1AOI with the protein and DNA as a cartoon. Colour Ile66 blue. |

Every task here is the twin of an MVS task (same prompt, same target atoms). A twin is
built where the requested state is one `color` call on a bare load, because pdbe-molstar
already draws the polymer as a cartoon and ligands as ball-and-stick. Four MVS templates
have no twin:

- `acc-residue-copy`, `acc-metal-copy`, `acc-metal-which` need an *added* representation
  (sticks on a residue, spacefill on an ion). In pdbe-molstar 3.3.2 that request has
  further end states that differ only in what happens to the default drawing under the
  added one (ribbon overpainted or not; the ion's default ball-and-stick still there).
  That is a property of the call format, not of the request, so the accept set would no
  longer measure "which copy?" alone.
- `acc-representation-open`: after a bare load the ligand is already drawn, so "show it
  in <colour>" has one obvious end state (overpaint it); nothing is left open.

With five templates of three tasks each, a template is 20% of this small tier (the
~12% cap holds on the MVS track: nine templates, at most three tasks each).

## How each reference is derived

| family | from the frozen data | accept rule |
|---|---|---|
| `acc-ligand-which` | `facts.ligands` of kind `ligand`: exactly two components, one copy each, ≥ 8 heavy atoms, entry not a membrane protein (panel feature); states = A, B, A+B (+ Mol*'s static `ligand` on MVS when it differs) | The entry has exactly two different ligands, one copy each, and the request says "the ligand". Accepted: either ligand alone, or both. On the MVS track also the viewer's own built-in 'ligand' selection when it is not the same atoms (Mol* adds residues covalently bonded to a ligand), because an answer that uses the viewer's word for exactly what was asked is not wrong. |
| `acc-ligand-colours` | same entries as above; two colours by seed; both assignments | The entry has exactly two different ligands, one copy each; the request gives two colours, "one ... and the other ...". Accepted: both assignments. |
| `acc-chain-colours` | polymer chains from `facts.chains`; exactly 2 or 3; n colours by seed; all n! assignments | The request gives one colour per chain but not which chain gets which. Accepted: every one-to-one assignment of the named colours to the polymer chains (n! states), on a cartoon of the whole polymer. |
| `acc-ligand-copy` | a `ligand` component with 2–4 copies (≥ 8 heavy atoms); each copy, and all | The request names one ligand; the entry holds several copies of it. Accepted: any one copy, or every copy. Not an arbitrary several-but-not-all: no reading of the request picks, say, two of four. |
| `acc-residue-colour` | as above, coloured on the cartoon instead of added as sticks | The request asks to colour a residue, named by type and author number but with no chain; the protein is present as several identical chains. Accepted: the residue coloured in any one chain, or in every chain. |

"Colour the chains differently" with no colours named is not here either: on the MVS

track no grading rule for "any distinct colours" exists yet. `acc-chain-colours` is the
enumerable neighbour: the colours are named, the assignment is not.

## Rules shared by all templates

- Structures: PDB entries of the panel with one model and at most 15,000 atoms; never 1HSG. At most 6 tasks of the tier (both tracks) on one structure.
- "Any one, or all": with more than two copies, a several-but-not-all answer is not accepted, because no reading of the request picks it.
- Held-back structures are not chosen per tier, because the validator refuses a structure used by both splits anywhere in the corpus: they are the corpus-wide list in `data/panel/heldback.json` when that file exists (or `--heldback-file`), and until then a fixed fifth of the panel by hash of the entry id (`heldback_structures()`). About a fifth of the tier's tasks are on them. In this tier: 1f88, 1igt, 1udt, 3ave, 8k7f.
- The cartoon is not given a colour by the request, so the reference leaves it at the viewer's default.
