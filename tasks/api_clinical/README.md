# Clinical-variant tier, API (pdbe-molstar 3.3.2 calls) track

Generated by `scripts/generate_clinical_tasks.py`; do not edit by hand. 85 tasks on 33 structures of 27 disease proteins. Every task has a twin with the same prompt and the same target atoms in `tasks/mvs_clinical/` (`twin_of`).

Each task names a structure and one or more missense variants that ClinVar itself classifies as pathogenic or likely pathogenic (the frozen, ClinVar-confirmed lists in `data/panel/variants/`), and asks for the residue each variant replaces to be shown. The structure holds the wild-type residue; the task is to find it. The prompt names the structure and the variant, never which residue of the structure it is.

pdbe-molstar resolves uniprot_accession + uniprot_residue_number itself (SIFTS), so this API task tests knowing that selector and supplying the accession; its MVS twin tests doing the UniProt-to-structure mapping. Half of the prompts give the UniProt accession and half give only the gene and protein name (`provenance.clinical.difficulty.accession_in_prompt`), so the second half also needs the accession from memory.

## How each reference is derived

| part of the reference | derived from | checked by |
|---|---|---|
| which variants | `data/panel/variants/<ACC>.json`: missense variants whose ClinVar variant record has the aggregate germline classification Pathogenic, Likely pathogenic or Pathogenic/Likely pathogenic. A short list of well-known variants (`FEATURED` in the script) is preferred when the frozen data confirms them; otherwise a seeded draw, strongly reviewed records first | the prompt's classification words are the frozen classification (`molbench.variants.classification_words`) |
| the target residue(s) | the variant's `structures.<entry>` residues in the same file (SIFTS mapping; listed only where the structure has the wild-type amino acid), in every copy of the protein or in the one named chain. Only variants modelled in every copy are used | the atom set is the same by label numbering, by author numbering and by `molbench.sifts.uniprot_atoms`; the residue name is the wild type |
| mature-protein name (legacy templates) | UniProt's processing features, frozen in `data/clinical/uniprot_processing.json`: number = UniProt position minus the residues before the single mature chain. Used only where the structure's author number of the residue is that number, or on the AlphaFold model paired with such a structure | `molbench.variants.mature_numbering` refuses proteins with several products or inexact features |
| helix or strand (sse templates) | `helices` / `strands` of `data/panel/facts/<entry>.json` (the entry's own annotation); the element must be the only one holding the residue, at least four residues, with no numbering break | same atoms by author and by label range; contains the target |
| representation, colours, wording | seeded draw from fixed lists | colours are in the task palette |
| call list | `load`, then one `color` call: each variant as `uniprot_accession` + `uniprot_residue_number` (with `auth_asym_id` when one chain is named) with `representation` and `representationColor`; with a whole-structure cartoon also `non_selected_color`; with a helix or strand also its author range | grades itself: success, F1 = 1, target score 1 |
| accepted alternatives | the residue's own stretch of cartoon may also take the highlight colour (`color` on the item; the reference leaves it as its surroundings); with a whole-structure cartoon, `set_visual_style: cartoon` may be set first. Nothing else is accepted | each grades as itself and is accepted by the task |

Every task also carries a grounding pack (`grounding`, rule `clinical-v1`, built by `scripts/build_grounding_packs.py`): the entry's chains and numbering runs, the SIFTS mapping, and the structure residues at each variant's UniProt position.

## What is recorded for analysis

`provenance.clinical` holds the gene, accession, the variant(s) with their ClinVar records, the residues, the template choices, a `pair` link, and `difficulty`: whether the residue's author number differs from the UniProt number (`needs_numbering_offset`, `author_minus_uniprot`), whether author and label chain ids or numbers differ, insertion codes, whether the accession is in the prompt, the number of copies, and two graded facts: whether an answer that uses the number in the variant's name as the author residue number, or as the label residue number, is right. `number_in_name_as_author_number_is_same_amino_acid` marks the tasks where that face-value residue is a different residue of the same amino acid, so checking the wild type does not expose the mistake; this happens only under an HGVS name, never under a bare one-letter name (the generator refuses it). `name_read_as_mature_number_is_same_amino_acid` is the same question for the other misreading: a name in UniProt numbering taken for a mature-protein number (true, false, or null when the frozen data does not show that residue). A bare one-letter name is used only where it is false; otherwise the variant is asked by its HGVS name. The two tasks of a pair share the wording, the colours, the representation and the accession in the prompt, so only the structure differs.

## Left out, and why

- **A variant whose position is not modelled in the structure.** The right answer would be a scene that shows nothing, or a refusal; neither is a final viewer state the grader can score as right, so no such task is built. Variants are used only where every copy of the protein has the wild-type residue modelled.
- **The residues contacting a bound ligand.** The frozen facts hold no contact lists, so this cannot be derived without a new, verified computation.
- **"Hotspot" requests.** Dropped: the word has no computed definition a prompt could state briefly.
