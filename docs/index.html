Molecular-visualization benchmark

MolBench

Can LLM assistants turn natural-language requests — “show the heme as orange ball-and-stick”, “superpose the subunits and hide the waters” — into correct molecular visualizations? MolBench measures two distinct skills: authoring a declarative MolViewSpec scene (what the picture is) and controlling a live Mol* viewer through imperative API calls (what the tool does). Both are graded deterministically against frozen, correct-by-construction answers.

Leaderboard

Two tracks, two skills. MVS F1 (the primary ranking) scores scene authoring — the declarative MolViewSpec tree a model emits, matched against the reference by the atoms each selection picks out. A scene scores 0 unless Mol* would show it. API F1 scores tool control — the imperative Mol*/PDBeMolstar calls that drive a live viewer (superpose, hide waters, spin, focus), the operations a static scene cannot express. MVS F1: primary scene-authoring score, 70 tasks, 1 sample each, run 2026-10-18. Engine-neutral by design — though Mol* is currently the only viewer that implements MolViewSpec. Validated F1: the same scenes after the render-and-judge cascade (see Tiered grading). Valid scene: share of samples Mol* accepts and renders; the rest are invalid JSON, invalid MVS or failed to load, and score 0 — hover for the breakdown, click for every failing sample. Cond F1: scene quality over valid scenes only — the gap from MVS F1 is how much a model loses to broken output rather than to visualization error. API F1: the tool-control track, not re-run in October: these are the 2026-07-04 results (20 tasks, ×3 samples, same grader). Cost: the October MVS run at provider list prices (— = not reported). Key findings

What the leaderboard actually tells you — read these before the table.

FINDING 01 · THE HEADLINE

Output validity, not competence, drives the ranking

The MVS ranking is largely a valid-output ranking. Over valid scenes, every LLM clusters at 0.87–0.98 Cond F1 — yet the unconditional spread is ~0.84. Valid-scene rate alone correlates with MVS F1 at r = 0.996. Of the 266 failed samples, 227 are invalid JSON and 36 are JSON that Mol* rejects as MVS (3 more failed to load) — details.

nvidia/nemotron-3-super-120b-a12b is last among the LLMs (~0.08 MVS F1) yet scores ~0.90 Cond F1 — competent when its scene is valid, but it usually isn’t (valid scene 9%; 64 of 70 samples are invalid JSON).

FINDING 02

The best open model is at the closed frontier-small tier

The top open model, deepseek-v3.2 (0.92), beats the best closed model, claude-haiku-4-5 (0.87) at 7× lower cost ($0.0453 vs $0.3073 for the run). But “open” spans a wide range: gpt-oss-20b (0.25), nemotron-3-super-120b-a12b (0.08) sit at the bottom, mostly on invalid output.

FINDING 03

Regime spread is dominated by output reliability

Tasks span translation → structure-grounded → clinical. Across regimes the model spread runs ~0.67–1.00; in the expanded panel it tracks output validity — a few models rarely emit a valid scene — more than task difficulty. See the per-regime table below.

FINDING 04 · NOVEL

Clinical grounding into 3D structure

Tasks bridge clinical genetics and structure: ClinVar pathogenic variants mapped via UniProt + PDBe SIFTS numbering onto the correct residues (e.g. p53 R175H). No other molecular-viz benchmark does this.

FINDING 05

Grounding dossiers don’t lift scores

Adding a frozen fact sheet about each structure (chains, ligands, numbering) changes MVS F1 by -0.042 on average across 15 models. On the 647 task×model pairs whose scene is valid in both runs the effect is -0.005. FINDING 06

Without the MVS reference, no model writes a valid scene

With only the output contract (“bare”), 0 of 420 scenes are valid across 3 models, with or without a dossier. Mostly the JSON parses but Mol* rejects it — parameters written straight onto the node instead of under params. Models don’t know MVS from pretraining.

Prompting conditions (the 2×2)

Every model above ran with the spec prompt: the output contract plus a neutral MolViewSpec reference. We also ran it with a dossier — a grounding pack of facts about the task’s structure (chains, residue ranges, ligand codes and atom names, SIFTS/UniProt numbering, ClinVar positions), built offline and frozen with the task. And a bare prompt, the output contract only, on three models. 70 MVS tasks, 1 sample, run 2026-10-18.

Dossiers don’t help. Mean change in MVS F1: -0.042 over 15 models. On the 647 task×model pairs valid in both runs: -0.005 (66 better, 93 worse, 488 unchanged). The overall drop is more invalid output on the longer prompt (worst: qwen3-30b-a3b-instruct-2507, valid scenes 56% → 31%). On the 15 lookup-heavy tasks (clinical and resolve-by-name) the mean change is -0.021. 2 models pass +0.10 there — gpt-oss-120b (+0.16; +0.033 on the 4 valid in both), llama-4-maverick (+0.13; -0.044 on the 2 valid in both) — and 4 lose as much. With 15 tasks and one sample, one task flipping between invalid and valid moves the mean by ~0.05; the gains come from such flips, not from better answers. Bare: 0 valid scenes of 420.

Tiered grading

Tree-matching can under-credit a scene that renders the same through a different tree. The escalating grader renders each valid but imperfect scene and escalates only when needed: tree-match → visual diff → VLM judge. The visual diff rescues only near-identical renders (≤ 2 pixels changing by > 48 in any channel, at 256 px), because a one-residue highlight changes just a few pixels. Across 15 models it confirmed 127 of 285 imperfect scenes (45%) as the right scene — 48 pixel-identical, 79 judged the same by the VLM. That moves validated F1 by only +0.00 to +0.03: grading selections by the atoms they pick out already credits most equivalent namings.

Validated F1 uses a rescue-only policy: a task scores 1.0 when the cascade confirms it renders the reference scene, otherwise it keeps its tree-match score (the VLM gives a binary same/different, not a graded score). Perfect: tree match already 1.0, not rendered. Escalated: valid, imperfect scenes that were rendered. Pixel same / VLM same: rescued at the visual-diff / VLM tier. Different: the VLM saw a different scene. Failed: no valid scene, scores 0 (see failures). The VLM verdicts are not yet checked against human raters — see the side-by-side evidence in the evaluator gallery →. Judge: claude-opus-4-8.
